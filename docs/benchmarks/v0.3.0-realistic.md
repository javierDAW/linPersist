# Benchmark v0.3.0 · realistic-fleet detection envelope

> v0.3.0 is a **coverage release**, not a detection-envelope release.
> The agent grows three new modules (linger, tmpfiles, sysusers),
> ten new detection rules promoting previously-orphan signals to
> Q7, and three module-specific rules covering the new family. The
> 75-host `lab-realistic` fleet does NOT seed implants exercising
> any of the new vectors, so Q1 / Q4 / Q7 / Q8 / Q11 row counts
> stay byte-identical to v0.2.0; the lift will only become visible
> on fleets that contain the new implant shapes. Total record
> volume grows by **12.5 %** because the agent now sees vectors
> v0.2.0 was blind to.

**Run details**

| Field | Value |
| --- | --- |
| Agent version | `linpersist-v0.3.0` (HEAD `f8b5023`; binary functionally identical to merge commit `7b736af`, only docs commits above) |
| Benchmark date | 2026-05-21 |
| Fleet generator seed | 42 (unchanged from v0.1.0 / v0.2.0) |
| Fleet size | 75 hosts |
| Records collected | **35,349** (v0.2.0: 31,433 -- **+12.5 %**) |

| Iteration mode | `LINPERSIST_HOST_BINARY` bind-mount (no image rebuild) |

`v0.2.0-realistic.md` as the production reference. v0.2.0 remains
the historical baseline for FP-calibration lift; v0.3.0 measures

| **Q7** | precision 1.00, 22 / 22 (8 critical + 14 high in v0.2.0 numbering) | **22 / 22** (13 critical + 9 high) | Stable. Severity recount reflects the v0.3.0 rule-set; same rows. |

| **`systemd.linger`** (new) | n/a | **0 records** | lab containers have empty `/var/lib/systemd/linger/`. |
| **`systemd.tmpfiles`** (new) | n/a | **3,218 records** | Stock vendor `tmpfiles.d` baseline; zero `tmpfiles_creates_under_tmp` signals. |
| **`systemd.sysusers`** (new) | n/a | **698 records** | Stock vendor `sysusers.d` baseline; zero `sysusers_uid_zero` signals. |
| **10 orphan-signal Q7 rules** (new) | n/a | **0 fires on this fleet** | Pre-armed; require implants the lab does not seed. |
| **3 structural-family Q7 rules** (new) | n/a | **0 fires on this fleet** | Pre-armed; require linger / tmpfiles / sysusers implant shapes. |

**Three findings load this release**:

1. **Coverage expanded to the systemd structural family** (linger,
   tmpfiles, sysusers; ADR-0014). The agent now reads three
   sibling persistence vectors that v0.2.0 was blind to:
   user-mode systemd linger markers, boot-time file creation
   directives, and declarative user / group creation. Each ships
   with one module-specific signal and one module-specific
   `critical`/`high` detection rule (`tmpfiles_creates_payload_at_boot`,
   `sysusers_second_uid_zero`, `systemd_linger_non_root_account`).
2. **Ten previously-orphan signals promoted to Q7 actionability**.
   The signals catalog (ADR-0011) already emitted them from the
   agent side but no rule in `detections.yaml` was promoting them
   from Q5 visibility to Q7 alerting. The promotion is
   conservative: each new rule pairs the signal with a
   non-package-path or recent-mtime guard so the rule does not
   light up on baseline-vendor configurations. The 75-host lab
   fleet produces zero fires across all ten.
3. **Q9 calibration documented and structurally enforced** by the
   tmpfiles parser's deliberate omission of `exec_target`
   (ADR-0014). The pre-v0.3.0 tmpfiles draft mapped the directive
   target path to `exec_target`, polluting Q9 with 341 baseline
   rows. The current implementation leaves `exec_target` empty
   for "touch-this-path-no-exec" and "marker-only" modules; Q9
   stays at 17 rows, all true positives.

## What the new modules see in lab-realistic

The new modules are running and emitting records. The lab simply
does not seed implants in their shapes:

| Module | Records | Distinct loci | Module-specific signal | Module-specific Q7 fires |
| --- | ---: | ---: | ---: | ---: |
| `systemd.linger` | 0 | 0 | `systemd_linger_non_root` | 0 |
| `systemd.tmpfiles` | 3,218 | per-host varies | `tmpfiles_creates_under_tmp` | 0 |
| `systemd.sysusers` | 698 | per-host varies | `sysusers_uid_zero` | 0 |

The tmpfiles `recent_mtime_30d` records (24 across the fleet) and
sysusers `recent_mtime_7d` records (8 across the fleet) are
container build-time artifacts -- the same class of build-time
noise documented in v0.2.0 for the `passwd` module. They do not
trigger Q7 because no rule pairs them with implant-specific
guards.

**To exercise the new detection envelope** the fleet generator
needs three new fixture types (planned for v0.3.1-fleet):

- `/var/lib/systemd/linger/<low-priv>` paired with a malicious
  unit under `~/.config/systemd/user/`. Would fire
  `systemd_linger_non_root_account` (high) on this single host.
- A `/etc/tmpfiles.d/<implant>.conf` with
  `f /tmp/.cache/payload 0755 root root - /opt/.impl/agent`.
  Would fire `tmpfiles_creates_payload_at_boot` (critical).
- A `/etc/sysusers.d/<implant>.conf` with
  `u backdoor 0 "..." /root /bin/bash`. Would fire
  `sysusers_second_uid_zero` (critical) on this single host AND
  cross-correlate with the existing `second_uid_zero_account`
  rule on the resulting `/etc/passwd` record.

The integration tests under
`internal/testdata/golden/{linger,tmpfiles,sysusers}/` cover the
positive paths in isolation; the fleet-level test will land with
the v0.3.1 generator update.

## Q4 + Q9 — unchanged

Six Q4 hits and seventeen Q9 hits, byte-identical to v0.2.0:

- `/tmp/.s/cacher` orphans wired via `rsync-cache.service` on
  `r-db-amzn-03`, `r-db-deb-02`, `r-k8s-node-ubu-02`.
- `/tmp/.x/agent` orphans wired via `cron.d/update-poll` on
  `r-monitoring-ubu-03`, `r-web-amzn-01`, `r-web-deb-01`.

Q9 minus Q4 = 11 hosts × "currently armed implant" (payload on
disk). The detector remains the sharpest tool in the kit.

The v0.3.0 calibration of `exec_target` (ADR-0014) does not
change the row count -- tmpfiles is the only module that ever
attempted to populate the field incorrectly, and the pre-merge
implementation already did the right thing in `7b736af`. The
benchmark documents the rule for future module authors.

## Q7 — 22 / 22 (13 critical + 9 high)

The Q7 roll-call splits into the same four families v0.2.0
documented; the v0.3.0 severity ordering is now visible in the
text report:

**13 critical:**

- 8× `sudoers_nopasswd_all_backdoor` on `/etc/sudoers.d/20-jenkins`
  (operator-side CI tooling on build hosts) and
  `/etc/sudoers.d/zz_cibot` (seeded implant). Same FP-channel
  caveat as v0.2.0: distinguishable only by role tag, pending
  v0.3.1-fleet.
- 3× `second_uid_zero_account` on `passwd` records:
  `r-build-server-ubu-02`, `r-db-amzn-01`, `r-dev-ubu-04`. Three
  distros, three uid=0 backdoors.
- 2× `sudoers_nopasswd_all_backdoor` overlap with `zz_cibot`
  records on monitoring hosts.

**9 high:**

- 6× `payload_under_tmp_via_persistence` (the Q4 ∪ Q9 overlap).
- 3× `kmod_install_directive_implant` on
  `/etc/modprobe.d/zz_helper.conf` referencing `/bin/sh`.

All 22 are true positives. The 10 new orphan-signal rules and
the 3 structural-family rules do not contribute to this count
because the fleet does not seed their shapes.

## Q1 / Q3 — same singletons, new module rows skipped over

Q1 stays at 26 rows. The new module records (tmpfiles, sysusers)
mostly land in the "common across fleet" bucket (stock distro
vendor configs ship them with identical content across hosts of
the same distro family). They contribute to Q5's signal
distribution by adding `recent_mtime_*` records but do not
generate new LFA singletons in this fleet because no host has a
host-unique tmpfiles / sysusers directive.

**This is the expected shape**. The new modules SHOULD blend
into the baseline on a clean fleet. They earn their keep when an
attacker adds a host-unique directive -- which Q1 / Q2 / Q7 then
surface independently.

## Container-image caveats — unchanged

The three v0.2.0 caveats (passwd recent-mtime as build-time
noise, `live_process_attached = 0` across the `--rm` containers,
rpm DB stripping in minimized base images) carry over verbatim.
v0.3.0 adds one variant:

**4. `recent_mtime_30d` on tmpfiles records.** Container base
images timestamp `/usr/lib/tmpfiles.d/*.conf` at image-build
time. On real fleets, `recent_mtime_30d` on a vendor tmpfiles.d
source means the distro package was upgraded recently --
informative. In the lab it is build-time noise. Same filter
recipe as v0.2.0: `WHERE module != 'tmpfiles' OR
recent_records > <threshold>`. Three rules referenced from
docs/stacking-cookbook.md cover this.

## What's left for v0.3.1 and beyond

Ordered by expected lift:

1. **`v0.3.1-fleet` sprint** — Host tags
   (`--tag key=value`) + peer-group LFA by `(os_id, tag)` in Q3 +
   `linpersist-report --diff prev.ndjson curr.ndjson` time-series
   diff. The host-tag dimension unlocks the CI sudoers FP
   channel (collapses 30 build-host singletons into one row).
   ADR-0015 (planned).
2. **Lab fixtures for linger / tmpfiles / sysusers implants** so
   v0.3.x can measure the new detection rules end-to-end against
   the realistic fleet. The benchmark above documents the
   expected shape; the generator update is the missing piece.
3. **MITRE coverage panel** in the fleet report (Overview block).
   Cross-cuts `matrix.yaml` (technique IDs declared as covered)
   with live records (which techniques actually surfaced). Card
   in `cmd/linpersist-report/render*.go`.
4. **Container-stripped-manifest auto-tag**. The Q11 FPs caused
   by minimal base images (4 of 6 rows in v0.2.0) carry over to
   v0.3.0 unchanged. The detection heuristic and the
   `host_meta.tags = ["container_image_stripped"]` emission are
   shared work with v0.3.1-fleet.
5. **`signal: package_owned_modified`** — extend provenance
   (ADR-0009) to compare `content_sha256` against
   `/var/lib/dpkg/info/<pkg>.md5sums`. Catches replaced binaries
   that current provenance reports as `Owned`.
6. **apk backend for the provenance resolver**. Alpine still has
   no provenance enrichment.
7. **dbus.services**, **cloud-init**, **container persistence**
   (docker daemon.json + k8s static-pods) -- the v0.4.0 vector
   backlog.

## Closing

v0.3.0 is the *coverage* engineered version of the v0.2.0
detection envelope. Same lab, same 30 implants, same headline
row counts. The agent now sees 12.5 % more records than v0.2.0
on the same hosts because it walks three additional persistence
families. Thirteen new detection rules are pre-armed against
shapes the lab does not yet seed; the fleet round-trip for those
shapes is queued for v0.3.1.

Zero regressions. Tag `v0.3.0` is justified on coverage merit.
