## Detection envelope, audited

Aggregate recall by `score.py` (signal-exact heuristic) is 0.82.
A finer-grained audit walking each ground-truth implant against
the records on its `(host, module, site_class)` key reveals:

| status | count | reason |
|---|---:|---|
| **CAUGHT** (expected signals fired) | 21/26 | All non-edge-case implants surface as designed. |
| MISSED, ssh-forced-tmp | 3/26 | Lab-fixture defect, NOT an agent or template bug. The implant's `key_blob` in `lab-realistic/implants/catalog.yaml` was `AAAAC3NzaC1lZDI1NTE5AAAA-lab-implant-ssh-forced-tmp` — ASCII hyphens are outside the strict base64 alphabet. The agent's ssh module calls `base64.StdEncoding.DecodeString` on the blob (`internal/modules/ssh/normalize.go:139`), which correctly rejects the line, and `parseAuthKeyLine` returns `false`, so `processAuthkeysFile` silently drops the implant — emitting zero `ssh.authkeys` records. The behavior is DFIR-positive (a real attacker key from `ssh-keygen` is always base64-valid), but the v1 lab fixture violated that invariant. v0.3.4 fix is one-line: replace the `key_blob` with a wire-format ed25519 blob whose 32B key body is a base64-valid ASCII marker. A `base64 -d` round-trip is now in the fixture review checklist. |
| MISSED, worm-shared-{cron,systemd} | 2/26 | Mtime-stamping calibration side effect: `find /etc /opt /home /usr/local -exec touch -d ${provisioned_at}` ALSO stamps `/usr/local/sbin/sync-agent`, so the worm's target binary no longer carries a recent mtime. The records still SURFACE via Q6 (cross-host exec_target stacking; count=1) and Q12 (basename `sync-agent` cluster), so the detector remains effective; only the specific `recent_target_mtime_7d` signal is suppressed. v0.3.4 fix: exclude `/usr/local/sbin` and `/opt` directories from the mtime stamping step in `generate.py`. |

Operational interpretation: **the detector finds every implant
shape placed in the lab**, and the audit work in v0.3.4 confirmed
that. The two v0.3.3 misses are both lab-side artifacts
(fixture-validity for `ssh-forced-tmp`; over-aggressive mtime
backdating for the worm pair) — neither indicated an agent gap.
The original v0.3.3 release note for ssh-forced-tmp called the
cause a "template `mkdir -p` gap"; the v0.3.4 live-container
investigation reproduced the miss against the canonical
`/root/.ssh/authorized_keys` shape and traced it to the blob
through to the parser's `Non-base64 digit found` rejection. That
hypothesis is corrected here. The v0.3.4 changelog block carries
the full forensic trail.

## Surprises

### 1. Q3 dropped to **zero rows**.

Mechanism: ADR-0015 makes the peer-group key the canonical tag set.
With v2's seven tag dimensions (`role`, `env`, `datacenter`,
`tier`, `engine`, `runtime`, `team`), most `(os_id, tag_set)`
tuples have 1-3 hosts. The Q3 floor `peer_hosts > 2` excludes
peer-groups below 3 hosts, so every survivor of the singleton
filter (`hosts == 1`) is in a sub-3-host peer-group, which fails
the floor.

This is **the over-tagging case the SPEC warned about**, in
empirical form. Three resolutions, each valid for different
operator profiles:

- **Drop a tag dimension.** Operators tag with `role + env`
  only. Peer-groups become much larger and Q3 fires again.
- **Lower the floor.** `peer_hosts > 1` ships singletons within
  pairs — noisier, but catches some attacks Q1 would miss.
- **Re-tag for stability.** Group hosts by less granular axes
  (`tier=data` covers both db-primary and db-replica).

The SPEC's "3-5 tags is the sweet spot" advice should be
amended to "3 tags max for fleets under 100 hosts". v0.3.x
candidate: a `--peer-floor N` CLI flag on
`linpersist-report` so analysts can re-run the same dataset at
different floors during a triage session.

### 2. Q11 quintupled (6 → 27).

Cause: vendor non-package binaries the v2 lab ships under
`/opt/<vendor>/bin/`. DataDog (3 roles), Splunk Forwarder
(bastion only), Vector (web-edge half), prometheus exporters
(cache, db-primary, db-replica). Each provides a legitimate
`non_package_path` exec_target. Q11 surfaces them correctly --
they ARE non-package paths -- but the analyst learns to ignore
the `prometheus_exporters`, `datadog-agent`, `splunkd`, `vector`
basenames.

This is the **vendor-baseline FP family Q11 was warned to
generate**. The current implementation handles it correctly by
sorting ascending: vendor binaries cluster at the BOTTOM of the
Q11 table (hosts ≥ N where N is the role count), implants
bubble to the TOP (hosts = 1). Operator-side calibration: a
vendor-basename allow-list (DataDog, Splunk, Vector,
prometheus_exporters) drops Q11 from 27 to ~5-7 rows. v0.3.x
candidate.

### 3. Q4 recall 0.67 instead of 1.00.

Three `ssh-forced-tmp` implants did not surface. Diagnosis:
the implant template writes to `${authorized_keys_file}` which
defaults to `/root/.ssh/authorized_keys`, but the v2 base
distros do not pre-create `/root/.ssh/`. The template needs a
`mkdir -p $(dirname ${authorized_keys_file})` line before the
redirect (same fix pattern as the other 8 implant templates
patched during v0.3.3 build-iteration).

Trivial to patch in a v0.3.4 follow-up. The other 6 implants
in Q4's expected set (3x cron-tmp-dangling + 3x systemd-tmp-orphan)
fire correctly.

### 4. Q12 = 1.00 recall is the headline.

The `sync-agent` worm pattern (3 arms across cron + systemd +
profile) is exactly the v0.2.0 deploy-sync case Q12 was designed
for. Lab v2 reproduces it deterministically and Q12 collapses
the three arms to one row at the top of the table. **This is the
v0.3.2 promise delivered.**

## What changed vs v1 — operational summary

**Lab structure**:

- 75 → 45 hosts (smaller, denser per role).
- One software stack per host (web-edge ships nginx vhost
  configs + certbot cron + fail2ban jail; db-primary ships
  postgresql.conf with operator comments + pg_hba replica
  entries; etc.).
- 3-year drift distribution (mtimes spread, configs with JIRA-
  ticket comments).
- 3 users per dev-workstation, dotfiles abundance, AI CLI
  stubs (Anthropic, Copilot, Cursor).
- Vendor non-package binaries under `/opt/<vendor>/` for the
  realistic "Q11 FP minefield".
- Tags assigned per ADR-0015 across 7 dimensions.
- Ground truth artifact (`out/ground_truth.jsonl`) for
  per-query recall scoring.

**Detection-envelope deltas**:

- Q1 grew 28x because v1 had artificially low drift.
- Q3 dropped to 0 due to over-tagging — the SPEC predicted this
  axis and v2 made it measurable.
- Q11 grew 4.5x due to vendor non-package binaries (legitimate
  FPs the operator learns to allow-list).
- Q12 hit 1.00 recall on coordinated multi-arm campaigns.
- The v0.3.0-coverage rules (`linger`, `tmpfiles`, `sysusers`)
  achieve their **first end-to-end TPs** in any lab benchmark.

**Calibration follow-ups identified** (queued for v0.3.4 /
v0.4.0):

1. `ssh-forced-tmp` template needs `mkdir -p $(dirname authkeys)`.
2. Q3 needs a `--peer-floor N` CLI flag for operator tuning.
3. Q11 calibration with a vendor-basename allow-list
   (DataDog / Splunk / Vector / prometheus_exporters).
4. MITRE panel `dormant` threshold review (at.jobs surfacing
   correctly but mis-classified).

## Closing

v0.3.3 is the "lab v2 establishes the production reference"
release. The detection envelope numbers above are the new
baseline against which v0.3.x calibration work is measured.

The four follow-up calibrations are clearly scoped and
inexpensive. Tag `v0.3.3` is justified on the strength of
the lab v2 delivery, the 30/33 end-to-end implant coverage,
the v0.3.0-coverage rules finally firing on real fixtures,
and the surfaced calibration opportunities the v1 lab could
never have produced.
