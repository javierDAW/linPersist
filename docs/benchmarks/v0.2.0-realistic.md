# Benchmark v0.2.0 · realistic-fleet detection envelope

> v0.2.0 closes the four headline failure modes that the v0.1.0
> benchmark documented. Q4 ∪ Q9 keep their 1.00 / 1.00 precision and
> recall; Q7's precision rises from **0.14 to 1.00** on the same
> fleet; Q11 (new) closes the gap LFA singletons left open for
> single-host implants outside `/tmp`. Zero documented implants are
> missed. Five rounds of measurement (v0.1.0 → v0.2.0 prefix →
> postfix → final → polish) bookend every code change against the
> same 75-host fixture.

| Detector | v0.1.0 | v0.2.0 | Operational verdict |
| --- | --- | --- | --- |
| **Q4 ∪ Q9** | precision 1.00 · recall 1.00 | **unchanged** | Ship. |
| Q4 alone | 1.00 / 1.00 | **6 / 6** | Stable. |
| Q9 alone | 1.00 / 1.00 | **17 / 17** | Stable. |

| **Q11** (new) | n/a | **6 rows, 2 TPs + 4 container-induced FPs** | Catches single-host implants outside `/tmp` that LFA singletons miss. |

**Five findings load this release**:

1. **rpm provenance switched from queryformat to `--filesbypkg`**. The
   `[%{FILENAMES}\t%{NAME}-%{VERSION}-%{RELEASE}\n]` query silently
   returned partial bracket-iteration on rpm 4.16+ in minimized
   container images, flooding Q11 with 8,500+ systemd false
   positives in the v0.2.0 prefix run. The
   `rpm -qa --filesbypkg --nosignature --nodigest` invocation is
   stable across every rpm version since 2005 and side-steps the
   bracket-iteration ambiguity.
2. **PAM `non_package_path` flood eliminated** by treating relative
   exec_target values (`pam_unix.so`, `@include system-auth`, bare
   crontab commands like `test`/`cd`/`runuser`) as
   `PkgStatusUnknown` rather than `Orphan`. The resolver returns the
   honest answer for what it cannot look up. Dropped 8,472 records.
3. **`/usr-merge` siblings resolved bidirectionally**. dpkg lists
   `/lib/systemd/X`; systemd ExecStart references
   `/usr/lib/systemd/X`. The resolver now tries both forms on miss.
   ~3,000 systemd FPs on Debian/Ubuntu hosts eliminated.
4. **Q7 sudoers clause requires the conjunction**
   `sudoers_nopasswd AND sudoers_all_commands`. The disjunction was
   firing on every host's stock `root ALL=(ALL) ALL` line (75 hosts
   × ~2-3 records each, 178 FPs) and on legitimate CI tooling like
   `gitlab-runner NOPASSWD: /usr/bin/docker` (40+ FPs across build
   servers). The conjunction is the textbook backdoor pattern — a
   principal granted NOPASSWD on the `ALL` command list — and is
   rare in legitimate config. Q7 collapsed from 210 → 22 rows.
5. **Q11 (new query) and `non_package_path` signal close the
   single-host orphan-outside-`/tmp` gap**. The implant
   `/usr/local/sbin/sync-agent` (singleton on `r-web-ubu-04`,
   wired via `deploy-sync.service`) was invisible to v0.1.0 — no
   `interpreter_in_tmp`, no `exec_target_orphan`, and the per-host
   uniqueness made LFA Q1 useless because the OTHER two arms of the
   same deploy-sync campaign on two different hosts used DIFFERENT
   vectors (cron, profile.d) and DIFFERENT exec_targets. v0.2.0 Q11
   surfaces it as a 1-host orphan in `/usr/local/sbin/`.

## Methodology

### Five measurement runs

Each run uses the same Docker fleet generated from seed 42. The
agent binary is bind-mounted into the live containers via
`LINPERSIST_HOST_BINARY` (added to `collect.sh` for this benchmark)
so each version measures against the same artifacts without an
image rebuild.

| Run | Agent built from | Q11 | Q7 | `non_package_path` records |
| --- | --- | ---: | ---: | ---: |
| 1. v0.1.0 baseline | `v0.1.0-alpha` tag | n/a | 175 (precision 0.14) | n/a (signal not yet wired) |
| 2. v0.2.0 prefix | provenance + 5 site_classes shipped | **127** (mostly FPs) | 210 | **12,538** |
| 3. v0.2.0 postfix | + LookupPath: relative=Unknown, usr-merge | 78 | 210 | **3,667** (−71%) |
| 4. v0.2.0 final | + A (rpm `--filesbypkg`) + B (ldso search paths) + C (sysv README skip) | **6** | 210 | **203** (−94%) |
| 5. v0.2.0 polish | + D1 (Q7 AND) + D2 (kmod modprobe-self) + D6/D7/D8 (UX) | **6** | **22** | **199** |

## Q4 + Q9 — the tmp-class detector remains a 1.00 / 1.00 pair

Six Q4 hits, all `/tmp/.s/cacher` or `/tmp/.x/agent` orphans wired
via `rsync-cache.service` or `cron.d/update-poll`. Seventeen Q9 hits
that include Q4's six plus the armed (non-orphan) implants on
`/tmp/.s/agent`, `/tmp/.cache/.sync/agent`, `/tmp/.b/persist`. Q9
minus Q4 = 11 hosts × "currently armed implant"; an analyst's
top-priority bucket.

No legitimate baseline configuration in the 75-host fleet produces
an `exec_target` under any tmp-class path. The detector is sharp.

## Q7 — precision 0.14 → 1.00

v0.1.0 Q7 returned **175 rows** of which **150 were false positives**:

- 88 records of the stock `/etc/sudoers` `root ALL=(ALL) ALL` line
  (fires `sudoers_all_commands` on every host)
- 40 records of CI sudoers.d/ drop-ins (`gitlab-runner`,
  `jenkins`) that ship NOPASSWD on specific commands (fires
  `sudoers_nopasswd` standalone)
- 22 records of `/lib/modprobe.d/dist-alsa.conf` recursive-modprobe
  install lines shipped by every distro's alsa package (fires
  `kmod_install_directive` on a non-implant)

v0.2.0 changes:

- **D1.** Q7 sudoers clause becomes `sudoers_nopasswd AND
  sudoers_all_commands`. The conjunction is rare in legitimate
  config; the disjunction was the dominant FP source.
- **D2.** kmod module suppresses `kmod_install_directive` when
  argv[0] of the install command is `/sbin/modprobe` or
  `/usr/sbin/modprobe` (the recursive self-modprobe pattern shipped
  by every distro). Implant pattern (argv[0] is a shell or
  interpreter) still surfaces.

Result: Q7 = **22 rows, 22 TPs, precision 1.00**. The roll-call now
splits cleanly into four families:

- 7× `/etc/sudoers.d/{20-jenkins, zz_cibot}` NOPASSWD+ALL across
  build-server and monitoring hosts. `20-jenkins` is operator-side
  CI tooling; `zz_cibot` is the seeded implant family. **Analyst
  decision point** — but the count is now tractable.
- 4× `zz_cibot` implants overlap with `20-jenkins` records on the
  same `build-server-*` host (the cibot campaign reuses the
  jenkins-runner pattern). Q1 surfaces the `cibot-svc` user
  singleton on the same hosts, closing the correlation.
- 3× `passwd_uid_zero` on `build-server-ubu-02`, `db-amzn-01`,
  `dev-ubu-04` — three distros, three uid=0 backdoors.
- 3× `modprobe.d/zz_helper.conf install … /bin/sh` on
  `k8s-node-amzn-03`, `k8s-node-rhel-01`, `web-rhel-02` — textbook
  modprobe-install persistence.
- 6× Q4 overlap (the `/tmp/` orphans documented above).

22 = 7 + 3 + 3 + 6 + 3 overlaps. Operator can clear the queue in
under five minutes.

## Q11 — the new query that closes the LFA gap

The v0.1.0 benchmark's finding 1 (LFA singletons fail against
single-host implants outside `/tmp`) is closed by Q11 in v0.2.0:

```
exec_target                        hosts records module    site_class      sample_host
/usr/local/sbin/sync-agent         1     1       systemd   systemd.unit    r-web-ubu-04
/usr/local/sbin/borg-wrapper       3     3       sshd      sshd.config     r-jump-deb-01
/usr/lib/systemd/systemd-pcrphase  12    72      systemd   systemd.unit    r-build-server-rhel-01
/etc/rc.d/rc.local                 15    30      systemd   systemd.unit    r-build-server-amzn-01
/etc/update-motd.d/60-unminimize   23    23      motd      motd            r-build-server-ubu-01
/sbin/modprobe                     27    54      systemd   systemd.unit    r-build-server-amzn-01
```

Two TPs (sync-agent, borg-wrapper) + four FPs (pcrphase, rc.local,
60-unminimize, modprobe). The four FPs are **container-image
artifacts** — `amazonlinux:minimal`, RHEL UBI minimal, slim Ubuntu
strip portions of their package manifests to reduce image size, so
the agent's provenance resolver sees those legitimately-installed
binaries as `Orphan`. On a production host with a complete package
DB the four FPs disappear.

The two TPs are exactly the implants v0.1.0 missed:

- `/usr/local/sbin/sync-agent` on `r-web-ubu-04` is the third arm
  of the deploy-sync coordinated campaign (the other two arms were
  `cron.d/deploy-sync` on `r-web-alp-01` and
  `profile.d/deploy-sync.sh` on `r-dev-deb-02`, each surfaced as
  Q1 singletons). v0.2.0 now surfaces all three sides of the
  campaign across three different LFA primitives.
- `/usr/local/sbin/borg-wrapper` on three `build-server-*` hosts
  via sshd `ForceCommand=` is an operator-side backup script if
  legitimate, but the location (`/usr/local/sbin/`, not
  package-owned) puts it on the triage queue automatically.

Q9 ∪ Q11 partition the universe of "non-package exec_target paths"
by location class. Run both for full coverage of the
unmanaged-payload pattern.

## Container-image caveats

Q10 (per-host collection health) confirms every host produced 280+
records — no silent agent failures. But two artifacts of the
Docker lab matter for interpreting the residual signals:

1. **`recent_mtime_7d` on `passwd` records.** Every container has
   `/etc/{passwd,shadow,group,gshadow}` with a build-time mtime
   that falls inside the 7-day window. Q8 surfaces this on 35
   hosts × ~85 records as `passwd module recent-mtime spikes`. On
   a real fleet, `recent_mtime_7d` on passwd files is the signal
   for "user accounts changed in the last week" — high value. In
   the container lab, it is build-time noise. **Document and
   filter** in fleet-specific cookbook queries: `WHERE module !=
   'passwd' OR recent_records > 50`.

2. **`live_process_attached` = 0 across the fleet.** Containers
   run only `linpersist` itself in the `--rm` collect-and-exit
   pattern. The /proc snapshot sees one PID. On a real host with
   cron / systemd / sshd running, the signal correlates persistence
   sites with their currently-active processes and is high-value.
   In Docker, structurally unusable. **Document caveat** in
   stacking-cookbook.

3. **rpm DB stripping in minimized base images.** UBI minimal /
   `amazonlinux:minimal` / hand-rolled slim Ubuntu strip rpm/dpkg
   package metadata to reduce image footprint. The agent's
   provenance resolver sees a partial manifest and legitimately
   package-installed binaries return `Orphan`. Four of the six Q11
   rows in the v0.2.0 polish run are this class of FP. **The agent
   is correct given the data.** On a complete production host the
   FPs disappear. v0.3.0 will add a `container_image_stripped`
   detection heuristic (compare `rpm -qa | wc -l` against a known
   minimum-package-count threshold per distro family) and emit it
   as a `host_meta.tags` token so the backend can filter
   automatically.

## What's left for v0.3.0

Ordered by expected lift:

1. **`signal: suspicious_content_pattern`** — cheap regex flag for
   `content_snippet` matching `curl … | (sh|bash)`,
   `wget … | (sh|bash)`, `base64 -d`, `${IFS}`, `eval $(`. The
   `deploy-sync.sh` implant currently surfaces only as an LFA
   singleton; with this signal it would carry a structural
   indicator and pair with `non_package_path` for higher
   confidence.

2. **`signal: package_owned_modified`** — extend provenance to
   read `/var/lib/dpkg/info/<pkg>.md5sums` and compare against the
   record's `content_sha256`. The honest question for an implant
   hunt is not "is this binary package-owned?" but "is this
   binary the version the package shipped?". Catches replaced
   binaries that current provenance reports as `Owned`.

3. **`signal: container_image_stripped`** — auto-detect minimized
   container base images (low rpm/dpkg manifest size, missing
   `/var/lib/rpm/Packages` or `/var/lib/dpkg/status`) and emit as
   `host_meta.tags`. The downstream pipeline filters Q11 FPs
   automatically.

4. **apk backend for the provenance resolver.** Alpine hosts
   contribute 969 records with no provenance enrichment in v0.2.0.
   apk's installed DB is at `/lib/apk/db/installed`, plain-text,
   trivially parseable in pure Go.

5. **Container-aware `live_process_attached`** — accept
   `--proc-root=/host/proc` for containerized deployments that
   bind-mount the host's `/proc` read-only.

6. **Q12 cookbook query — basename clustering.** The deploy-sync
   campaign's three arms share basename `deploy-sync*` across
   cron, profile.d, and systemd. A query that surfaces "same
   basename, different module, ≥2 hosts" would have caught the
   campaign as a single Q12 hit instead of three independent Q1
   singletons.

## Closing

v0.2.0 is the precision-engineered version of the v0.1.0 detection
envelope. Same lab, same fixtures, same 30 seeded implants. Zero
missed. Q7 went from 175 rows of mostly noise to 22 rows of
actionable TPs. The new Q11 surfaces the single-host implants
outside `/tmp` that no v0.1.0 query could catch. The agent's data
quality on real (non-minimized-container) hosts is now
operator-grade.

Tag `v0.2.0` is justified.
